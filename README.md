# ツーリング雨予報チェッカー

バイクツーリングのルートを入力すると、出発時刻から各地点への到着予定時刻を計算し、その時刻の天気予報（降水確率・降水量）をチェックして、道中で雨に降られる可能性のある区間を地図上に色分け表示するアプリです。ルート上の主要地点には気温・天気も表示します。

## 主な機能

- **ルート入力**: 出発地・目的地（住所/地名でオートコンプレート検索）、経由地を最大5件まで追加可能、出発時刻の指定
- **雨リスク判定**: 出発時刻からルート沿いの各地点への到着予定時刻を計算し、その時刻の降水確率・降水量をもとに区間ごとに 低/中/高 のリスクを判定。地図上でポリラインを緑/黄/赤に色分け表示
- **地点別の天気・気温一覧**: ルート上の主要地点（最大15件）の気温・天気・降水確率を地図上のマーカー（クリックで詳細表示）と、地図とは別の一覧リストの両方で表示。降水確率は高いが天気表示自体は「晴れ」系の場合は注記を表示
- **共有リンク**: 検索結果はURLに自動反映される（`?trip=...`）。「共有リンクをコピー」ボタンでURLをコピーでき、そのURLを開くと同じ条件で自動的に再検索される（サーバー保存やアカウント登録は不要）
- **Googleマップで開く**: 検索したルートをそのままGoogleマップアプリ/Web版で開き、実際のナビに引き継げる
- レスポンシブな2カラムレイアウト（左: 入力フォーム、右: 地図・一覧）。スマートフォン幅でも利用可能

## 技術スタック

- **フレームワーク**: Next.js 16（App Router）+ React 19 + TypeScript
- **スタイリング**: Tailwind CSS 4
- **バリデーション**: Zod 4（`POST /api/route` のリクエスト検証と、共有URLの復元検証の両方で同じスキーマを使用）
- **地図**: `@react-google-maps/api`（Google Maps JavaScript API のReactラッパー）。住所入力は Places API のオートコンプレート（レガシー版ウィジェットを使用）
- **ルート計算**: Google Directions API（サーバーサイドから呼び出し）
- **地点の地名変換**: Google Geocoding API（逆ジオコーディング、サーバーサイド）
- **天気データ**: [Open-Meteo](https://open-meteo.com/)（APIキー不要、時間別の降水確率・降水量・気温・天気コードを取得）
- **アーキテクチャ**: DBなしのステートレス構成。全ての処理は `POST /api/route` 単一のRoute Handlerに集約し、Google/Open-MeteoのAPIキーはサーバー側のみで使用（ブラウザには一切露出しない）。共有機能もサーバー保存ではなくURLクエリパラメータへのエンコードのみで実現

## セットアップ

### 1. APIキーの取得

必要なAPIキーは **Google Maps用の2種類のみ** です。天気データは [Open-Meteo](https://open-meteo.com/) を使用しており、非商用利用であればAPIキー登録・クレジットカード登録は不要です。

#### Google Maps（2種類のキーを発行する）

1. [Google Cloud Console](https://console.cloud.google.com/) にアクセスし、Googleアカウントでログインする。
2. 画面上部のプロジェクト選択メニューから「新しいプロジェクト」を作成する（既存プロジェクトを使い回してもよい）。
3. 左メニュー「お支払い」からこのプロジェクトに請求先アカウント（クレジットカード）を紐付ける。Directions APIなどは無料枠を超えると課金対象になるため必須。
4. 左メニュー「APIとサービス」→「ライブラリ」で以下4つを検索して有効化する。
   - **Directions API**
   - **Geocoding API**（ルート上の地点を地名に変換するため）
   - **Maps JavaScript API**
   - **Places API**
5. 「APIとサービス」→「認証情報」→「認証情報を作成」→「APIキー」で **サーバー用キー** を作成する。
   - キー作成後「キーを制限」を開き、「アプリケーションの制限」は IPアドレス（サーバーのIPが固定できない場合は「なし」のままでよい）、「APIの制限」は **Directions API と Geocoding API** にチェックを入れて保存する。
   - このキーが `.env.local` の `GOOGLE_MAPS_SERVER_API_KEY` になる。
6. 同様にもう1つ「APIキーを作成」して **ブラウザ用キー** を作る。
   - 「アプリケーションの制限」は「HTTPリファラー（ウェブサイト）」を選び、`http://localhost:3000/*` と本番公開時のドメイン（例: `https://your-app.example.com/*`）を追加する。
   - 「APIの制限」は **Maps JavaScript API と Places API** の2つにチェックを入れて保存する。
   - このキーが `.env.local` の `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_API_KEY` になる（ブラウザに露出する前提のキーなので、このリファラー制限が唯一の防御線）。

### 2. 環境変数の設定

```bash
cp .env.example .env.local
```

`.env.local` を編集し、取得した2つのキーを設定してください。

```
GOOGLE_MAPS_SERVER_API_KEY=...
NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_API_KEY=...
```

### 3. 起動

```bash
pnpm install
pnpm dev
```

[http://localhost:3000](http://localhost:3000) を開いてください。

## 既知の制約

- Open-Meteoの時間別予報は最大16日先まで取得できますが、数日以上先の予報は一般に精度が下がります。
- 経由地は最大5件まで（UIの使いやすさと共有URLの長さを抑えるための制限。Google Directions API自体はより多くの経由地に対応可能）。
- 地図上の主要地点マーカーは最大15件（出発地・目的地はユーザー入力の地名をそのまま使用、中間地点はGeocoding APIで逆引き）。逆ジオコーディングに失敗した地点は「地点N」という汎用ラベルにフォールバックします。
- 複数ルート案の比較（Directions APIの `alternatives`）、GPXインポート、出発時刻の調整提案は現時点では未対応です。
